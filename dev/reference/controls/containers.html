Container controls

Use the smallest container that states the allocation rule. The layout guide explains constraints and size flags; the ownership guide explains logical versus visual parentage.

Role Types
Base ownership/template Control, Container, TemplatedControl, Panel, PanelContainer
Axis and flow BoxContainer, HBoxContainer, VBoxContainer, FlowContainer, HFlowContainer, VFlowContainer, StackPanel, WrapPanel, FlexPanel
Grid and placement GridContainer, GridPanel, CanvasPanel, OverlayPanel, CenterContainer
Insets and transforms MarginContainer, Border, AspectRatioContainer, Viewbox
Content and projection ContentControl, ContentPresenter
Scrolling ScrollContainer, ScrollPresenter, ScrollBar, HScrollBar, VScrollBar
Splitting SplitContainer, HSplitContainer, VSplitContainer, SplitContainerDragger, SplitContainerMultiDragger
Disclosure/pages FoldableContainer, TabContainer

GridContainer.Columns clamps to at least one. BoxContainer defaults to vertical orientation and theme-derived separation. ContentControl accepts one content value. Presenter and dragger types are primarily template parts, not first-choice application roots. Avoid nested same-axis scroll owners.

Containers expose their logical child peers. Scroll, tab, and foldable controls add scroll-view, tab-panel, or group semantics. Base accessible naming falls back from AccessibilityLabel to Name; assign a user-facing label when an internal name is not meaningful.

Catalog: GridPanel, ScrollContainer, SplitContainer, WrapPanel.

Every public type in the tables has a Catalog story with the exact unqualified type name. Its stable identifier is catalog- plus the kebab-case type name, such as catalog-grid-panel; the Catalog's Open reference link returns to this page.
