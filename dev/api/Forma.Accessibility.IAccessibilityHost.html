Remarks

The interface has to fit two shapes, not just two platforms, or it needs rewriting at the first Windows attempt. On macOS the adapter is attached to the window's view and the system then calls into it. On Windows the adapter must answer a WM_GETOBJECT message from the window procedure — and the windowing backend owns that procedure. Attach(nint, Func<AccessibilityTreeSnapshot>, Action<AccessibilityActionRequest>) covers both: macOS installs a subclass there, Windows would install a window-procedure hook there.

A host must never throw for "this platform cannot do it" — it returns false from Attach(nint, Func<AccessibilityTreeSnapshot>, Action<AccessibilityActionRequest>). Accessibility being unavailable is a normal state, not an error, and an application should not have to guard against it.

bool Attach(nint windowHandle, Func<AccessibilityTreeSnapshot> requestTree, Action<AccessibilityActionRequest> performAction)

Parameters

windowHandle nint

The operating system's window object — NSWindow*, HWND — not the windowing backend's. Zero means there is no window, which is the normal answer under a headless runtime.

requestTree Func<AccessibilityTreeSnapshot>

Called when the platform first activates accessibility, and thereafter whenever an update is pushed. Returns the current tree. It is called on the thread that owns the window.

performAction Action<AccessibilityActionRequest>

Called when an assistive technology requests an action. Also on the window's thread.

Returns

bool

False when accessibility could not be started, for any reason.
