Remarks

Forma never touches Objective-C here. macOS accessibility works by calling accessibilityChildren, accessibilityFocusedUIElement and accessibilityHitTest: on the window's view — and the windowing backend owns that view, so implementing them directly is not an option. The subclassing adapter installs a runtime Objective-C subclass carrying those methods and restores the original class when freed.

Everything here runs on the thread that owns the window. AccessKit's macOS adapter asserts the main thread internally and a violation is a Rust panic across the FFI boundary, which from managed code is a process abort rather than an exception — so the rule is enforced by not breaking it, not by catching it.

Parameters

windowHandle nint

The operating system's window object — NSWindow*, HWND — not the windowing backend's. Zero means there is no window, which is the normal answer under a headless runtime.

requestTree Func<AccessibilityTreeSnapshot>

Called when the platform first activates accessibility, and thereafter whenever an update is pushed. Returns the current tree. It is called on the thread that owns the window.

performAction Action<AccessibilityActionRequest>

Called when an assistive technology requests an action. Also on the window's thread.

Returns

bool

False when accessibility could not be started, for any reason.
